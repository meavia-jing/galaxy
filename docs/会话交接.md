## 5 六个容易踩的坑（都踩过，别重踩）

1. **`wsl -e bash -lc` 里的引号**：PowerShell 不认 `\"` 转义，多行脚本先写到 `%TEMP%` 再 `bash /mnt/c/...` 执行，否则命令会被拆散。
2. **部署脚本要 LF 换行**：从 Windows 侧新建的 `deploy/*.sh` 是 CRLF，直接跑会报 `bad interpreter`。执行前 `sed -i 's/\r$//' deploy/*.sh`。
3. **`systemctl reload nginx` 是异步的**：reload 后立刻 curl 可能打到旧配置（曾误报 301）。健康检查必须带重试。
4. **空库的备份演练毫无意义**：第一次演练四张表行数全是 0，「恢复成功」什么都没证明。演练前先确认源库非空（`SELECT COUNT(*)`）。
5. **安装到仓库根的 pip 包会让 SMK-14 失败**：`markdown` 的 1066 行文件被计入行数检查。临时依赖必须装到仓库外。
6. **停 Redis 后必须自己拉回来**：`Stop-Process` 掉 `redis-server` 后，用 `Start-Process -FilePath D:\redis\redis-server.exe -ArgumentList redis.conf -WorkingDirectory D:\redis` 恢复，否则后续冒烟 SMK-04 直接红。
7. **`Copy-Item` 还原被变异的文件会带回旧 mtime，dev server 不会重载**：Django `StatReloader` 只在 `mtime > 已记录值` 时才重启，于是服务一直跑着变异版本。曾因此误判「Redis 缓存 TTL 是 -1（永不过期）」。做变异检查后必须 `(Get-Item 文件).LastWriteTime = Get-Date`（或重启服务）再测真机。
