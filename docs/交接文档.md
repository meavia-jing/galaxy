## 5 已知缺陷与风险

### 5.1 高优先：Redis 故障导致 500 而非 503（已修复，待人工审核）

| 项 | 内容 |
| --- | --- |
| 现象（修复前） | 停掉 Redis 后 `POST /api/v1/auth/login/` 返回 **500 HTML 错误页**；`/api/v1/categories/`、`/api/v1/banners/` 同样 500 |
| 根因 | `LoginView.throttle_scope="auth_ip"`，`ScopedRateThrottle.allow_request` 读 Django cache，`redis.exceptions.ConnectionError` 未被捕获（`rest_framework/throttling.py:123` → `django/core/cache/backends/redis.py:188`） |
| 违反 | I02-T01「Redis 故障认证返回 503」、I03-T05「Redis 停机可回源」 |
| 修复 | ① `common/throttling.py` 限流器 fail-open；② `common/cache.py` 缓存读回源、写降级、失效不抛错；③ `common/exceptions.py` + `common/middleware.py` 未捕获异常返回 500 信封、依赖故障返回 503 信封（均带 `request_id`、无栈） |
| 证据 | `backend/tests/integration/test_error_contract.py` 9 条；停 Redis 实测分类/横幅 **200**、登录 **401 信封**、`/health/ready/` **503**；恢复 Redis 后 ready 回 `database=ok cache=ok`；冒烟 14/14 |
| 口径说明 | 修复按本文件原建议采用 fail-open：缓存故障时认证降级为「不限流但可用」，不再 503。I02-T01 验收语需人工确认是否改写为「缓存故障时认证仍可用」 |
| 状态 | 代码已交付（AI 已交付），人工验收未进行 |

### 5.2 中优先：并发行锁未被真实验证（已修复，待人工审核）

原 13 条地址用例继承 `django.test.TestCase`，每例包在事务内并回滚，`select_for_update()` 不会与自身阻塞，因此「并发设置默认地址后最多一个默认项」只有顺序执行的证据。

已补 `backend/tests/integration/test_address_concurrency.py`：`pytest.mark.django_db(transaction=True)`（等价 `transactional_db`）+ `threading.Barrier` 同步启动，每线程独立连接。覆盖 INT-ADR-01~05：首地址默认、并发切换默认恰好一条、越权隔离、并发删除默认+新增、并发新增不超过 20 条上限。5 条全部通过，无死锁超时。
