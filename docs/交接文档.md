### 5.2 中优先：并发行锁未被真实验证（已修复，待人工审核）

### 5.7 低优先：就绪探针 503 的 `error.code` 不是契约码（新发现，待修）

| 项 | 内容 |
| --- | --- |
| 现象 | 停掉 Redis 后 `GET /health/ready/` 返回 `HTTP 503`，但信封是 `{"error":{"code":"ERROR","message":"请求失败","fields":{"status":"degraded","checks":{"database":"ok","cache":"unavailable"}}}}` |
| 预期 | 503 的稳定错误码为 `DEPENDENCY_UNAVAILABLE`（`common/errors.py::DEFAULT_CODES`），字段结构也不应把整段 checks 塞进 `fields` |
| 根因 | `common/renderers.py` 对「状态码 ≥400 但响应体不是 `{"error": …}` 结构」的响应统一兜底成 `code="ERROR"`，就绪探针属于这一类 |
| 影响 | 监控/前端若按 code 分支判断会走兜底分支；HTTP 状态与 `checks` 内容本身正确，故不阻塞 I01 的「ready 503 / live 200」结论 |
| 发现方式 | 2026-11-22 停 Redis 复核 I02-T01 的 fail-open 时顺带观察到，非人工发现 |
| 建议修复 | 渲染器对裸 dict 的 4xx/5xx 改用 `DEFAULT_CODES` 映射 code/message，或在 `ReadyView` 显式返回 `{"error": {...}}` 并保留 `checks` |
| 状态 | **未修**，登记待 I10-T01 统一处理（改动会波及全部错误信封，不在基线收尾批次内做） |
