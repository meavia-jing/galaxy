## 验收口径（人工裁定，2026-11-17）

原验收语写作「超过架构限额返回 429；Redis 故障认证返回 503」，与「缓存只做加速器」的实现策略冲突：限流计数存在 Redis，Redis 不可用时若返回 503，等于让缓存故障升级为认证不可用。

**2026-11-17 人工裁定改写为：缓存故障时认证仍可用（限流 fail-open），返回 401 信封而非 500/503。** `迭代计划文档.md` §4 与本文、`docs/交接文档.md` §5.1 三处口径现已一致。

`backend/tests/integration/test_auth_flow.py` 与 `test_error_contract.py`，2026-11-22 16:28 全量跑通（86 passed）：

| 用例 | 验收条目 | 断言 |
| --- | --- | --- |
| `INT-AUTH-01` | 正常注册登录成功 | 注册 201 + access；refresh 只在 HttpOnly Cookie，响应体无 `refresh` |
| `INT-AUTH-02` | 大小写归一后不能重复 | `ALICE_xxx` 与 `  ALICE_xxx  ` 第二次注册返回 400，`fields.username` 含「已被使用」 |
| `INT-AUTH-03`（3 条参数化） | 弱密码拒绝 | 过短（<10）、纯数字、常见密码分别被拒，`fields.password` 给出对应原因 |
| `INT-ERR-05`（限流正向） | 超过限额返回 429 | 同一 IP 连续 31 次登录：前 30 次 401，第 31 次 429 `RATE_LIMITED` |
| `INT-ERR-05`（fail-open） | 缓存故障时认证仍可用 | `override_settings(CACHES=BROKEN_CACHES)` 下登录返回 200 且取得 access，日志含 `throttle bypassed` |

| `POST /api/v1/auth/login/`（错误密码） | 401 信封，不是 500/503 | `HTTP 401`，`{"error":{"code":"UNAUTHORIZED","message":"No active account found with the given credentials","fields":{}},"request_id":"ef255714de57…"}` | 通过 |

### 3 密码规则与用户名归一实现位置

| 要求 | 落地位置 |
| --- | --- |
| 用户名先 trim 转小写再按 `[a-z0-9_]{4,32}` 校验 | `accounts/models.py::USERNAME_RE`、`UserManager.normalize_username`、`RegisterSerializer.validate_username` |
| 密码最少 10 位 + 常见密码 + 纯数字 + 相似性校验 | `config/settings/base.py::AUTH_PASSWORD_VALIDATORS`，注册与改密均调用 `validate_password` |
