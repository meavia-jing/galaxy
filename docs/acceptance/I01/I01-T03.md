| 问题 | 处置 |
| --- | --- |
| `DatabaseBackedJWTAuthentication` 未被识别 | 新增 `common/schema.py::JWTAuthenticationScheme`（`OpenApiAuthenticationExtension` 子类），在 `common/authentication.py` 末尾导入以完成注册 |

## 权限基类验证

`common/permissions.py` 原为「写了但没启用」的状态，属于未验证的承诺。本迭代补 `backend/tests/unit/test_permissions.py`（15 条）覆盖三个基类的正负路径，并在过程中修掉两个真实缺陷：

| 缺陷 | 现象 | 修复 |
| --- | --- | --- |
| `IsStaff` / `IsOperatorOrReadOnly` | 用户模型缺少 `is_staff_allowed`/`is_operator` 属性时抛 `AttributeError`（500），而不是拒绝 | 改用 `getattr(..., False)` 兜底 |
| `IsOwner` | 对象既无 `user_id` 也无 `user` 时，`owner_id` 为 `None`，若请求用户 `id` 也为 `None` 则放行 | 补 `owner_id is not None` 前置判断 |

| 用例 | 断言 |
| --- | --- |
| `UNIT-PERM-01`（5 条） | `user_id` 匹配放行；他人对象拒绝；`user` 关联可读；无归属字段拒绝；中文提示语 |
| `UNIT-PERM-02`（6 条） | `GET/HEAD/OPTIONS` 匿名放行；写操作需 `is_operator`；匿名写即使标记 operator 也拒绝 |
| `UNIT-PERM-03`（4 条） | staff 放行；非 staff 拒绝；匿名拒绝；属性缺失时拒绝而不抛异常 |

> 说明：三个基类当前尚无视图消费，消费方在 I02 用户中心与 I06 优惠券引入。此处通过单元测试把「基类行为正确」固定下来，而不是留到业务任务里才发现。
