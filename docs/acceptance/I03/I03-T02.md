### 接口清单

| 方法与路径 | 权限 | 说明 |
| --- | --- | --- |
| `GET /api/v1/categories/` | 游客 | 启用中的分类，60 秒缓存（见 I03-T05） |
| `GET /api/v1/products/` | 游客 | 列表；参数 `category` / `keyword` / `sort` / `page` / `page_size` |
| `GET /api/v1/products/{id}/` | 游客 | 详情；含 `description` / `images` / `skus` |

公开端点显式 `authentication_classes = []`，避免 OpenAPI 把它们标成需要 Bearer，误导调用方。

### 分页

`common.pagination.StandardPagination`：默认 20 条，`page_size` 上限 **100**，响应为 `{items, page, page_size, total}`，比 DRF 默认的 `{count, next, previous}` 少一次「有没有下一页」的猜测。

真机验证（8 个在架商品）：

```text
PAGE_SIZE_101 => HTTP 200 page=1 page_size=100 total=8 items=8   # 超过上限被收敛，不报错
PAGE2_SIZE5   => HTTP 200 page=2 items=3 total=8                 # 末页只剩 3 条
```

### 排序白名单与价格排序的坑

`price_asc` / `price_desc` 需要按「最低价」排序，用 `annotate(price_min=Coalesce(Min("skus__price", filter=Q(skus__is_active=True)), Decimal("0.00")))`。首跑即暴露 500：`Coalesce` 不接受 `DecimalField` 与 `IntegerField`（写了 `0` 而不是 `Decimal("0.00")`）混用。修复后四种排序全部通过（INT-CAT-04 参数化 4 次）。

### 序列化字段

列表卡片只返回渲染所需字段（`id/title/slug/subtitle/category_id/category_name/price_min/price_max/cover_image/is_featured`），价格区间由**预取好的** SKU 集合在内存里算 min/max，不额外打库（见 I03-T05 的 SQL 计数）。详情在此基础上追加 `description/images/skus`，`skus` 只含 `is_active=True`。

## 真机实况（dev server + 开发库）

```text
LIST_DEFAULT      => HTTP 200  items[0]=折叠露营椅 ¥239.00（newest 默认）
LIST_CATEGORY=digital => HTTP 200  仅「数码影音」下商品
LIST_KEYWORD=无人机    => HTTP 200  page=1 page_size=20 total=0（无命中给空数组，不报错）
LIST_SORT_PRICE_DESC  => HTTP 200  首条 ¥1599.00 便携显示器，次条 ¥1349 耳机
LIST_BAD_SORT=rating  => HTTP 400  {"error":{"code":"INVALID_SORT","message":"排序参数不在允许范围内","fields":{}}}
DETAIL /products/1/   => HTTP 200  price_min 1299.00 / price_max 1349.00，含 images 与 skus
DETAIL /products/999999/ => HTTP 404  {"error":{"code":"NOT_FOUND","message":"商品不存在或已下架"}}
```

错误响应均带 `request_id`，可直接与后端日志对齐。

## 已知问题

1. `keyword` 只做 `icontains`，没有相关度排序与中文分词：搜「耳机」命中标题含「耳机」的商品，但同义词（「耳麦」）与拼写错误不命中。数据量到万级时应换全文索引。
2. 分类筛选只接受 `slug`，不支持「该分类及其子分类」的级联筛选。当前只有一级分类，暂不影响。
3. 页码超出范围时 DRF 抛 `NotFound`，被全局异常处理器包装为 `NOT_FOUND` + 中文消息「无效页面。」（真机 `?page=99` → HTTP 404）。语义上是「参数无效」而不是「资源不存在」，与 `INVALID_SORT` 的命名口径不完全一致；前端已用 `totalPages` 收敛，正常路径不会触发，登记为口径待统一（与交接文档 §5.7 的 `DEPENDENCY_UNAVAILABLE` 一起在 I10-T01 处理）。
4. 列表未提供「总页数」，前端用 `Math.ceil(total / 20)` 自行计算；若将来改默认页大小，前后端需同步。
