### 为什么筛选条件放 URL

`selectCategory` / `submitSearch` / `changeSort` / 翻页全部走 `router.push({ query })`，组件用 `watch(() => route.query)` 重新拉数据。好处：刷新不丢筛选、链接可分享、浏览器后退符合直觉；代价是每次筛选多一次路由跳转（已在真机确认无可感延迟）。

### 规格切换的取值口径

```text
价格 = selectedSku.price ?? product.price_min      # 未选中时用区间下限兜底
库存 = selectedSku.stock_available ?? 0
按钮 = 库存 > 0 ? 「加入购物车」: 「暂时缺货」（disabled）
数量 = clamp(输入, 1, min(99, 库存))                 # 最终仍以服务端校验为准
```

`clampQuantity()` 刻意在前端先收敛：避免把 `0`、`abc`、`9999` 这种明显非法值发给服务端；但注释里写明「最终以服务端为准」，不假装前端校验能替代后端。

## 已知问题

1. 列表页未做「滚动到底自动加载」，只有上一页/下一页；20 条一页对当前 8 个商品的演示数据足够，商品上千后体验会变差。
2. 切换规格只改价格与库存，不切换图集（`images` 已由接口返回，但界面固定展示首图）。要做「一规格一图」需给 `ProductImage` 加规格关联。
3. 详情页没有面包屑以外的分类回链，用户无法从详情直接跳到同分类列表。
4. 前端把默认页大小 20 写死在两个地方（`ProductListView` 的 `page_size: 20` 与 `totalPages` 的 `/ 20`），与后端 `StandardPagination.page_size` 是隐式约定，改动需同时改两处。
5. 未做图片懒加载与 `srcset`：原图直出，弱网首屏偏慢。
