# 自动化测试计划

版本：1.0｜编制日期：2026-11-15｜状态：待人工审核
关联文档：《迭代计划文档》第 1 节交付规则、第 14 节验收登记制度；《开发架构文档》第 9 节测试要求

> 本文件是测试方案，不含代码改动。用例清单见同目录 `用例矩阵.md`。

## 1 目的与范围

按「集成 / 冒烟 / 回归」三层组织自动化测试，并额外覆盖 AI 能力带来的脚本功能测试与 UI 自动化测试。目标是让每批迭代都有客观的准入门槛和出厂门槛，避免依赖人工点页面判断。

适用范围：`backend/`（Django + DRF）、`frontend/`（Vue 3 + TS）、`scripts/`（运维与门禁脚本）。

不在本计划范围：性能压测、安全渗透、数据库兼容性矩阵（属 I10-T02/T03），本计划只预留接口与数据目录。

### 2.1 已发现的测试盲点（必须在 B5 修复）

现有 `AddressApiTests` 继承 `django.test.TestCase`。`TestCase` 会把每个用例包在一个事务里并回滚，而 `select_for_update()` 在同一事务内不会与自身阻塞。因此：

- 代码里「并发设置默认地址后最多一个默认项」的实现（`apps/accounts/services.py` 的 `_lock_user`）**从未被真正验证过**；
- 现有 `test_switching_default_keeps_exactly_one` 只验证了**顺序执行**下的结果，不能作为并发证据；
- 验收记录 `docs/acceptance/I02/I02-T04.md` 中该项结论应重新表述为「顺序路径已通过，并发待 B5 补测」。

正确做法：并发用例必须使用 `pytest-django` 的 `transactional_db`（或 Django 的 `TransactionTestCase`），由多线程各持独立连接执行。

## 3 三层定义与判定标准

| 层 | 回答的问题 | 判定标准 | 运行时机 |
| --- | --- | --- | --- |
| **集成** | 模块之间能不能打通 | 跨 app、真实 MariaDB + Redis 的读写与状态流转通过；越权与状态冲突被正确拒绝 | 每次提交前、每批迭代收尾 |
| **冒烟** | 这个版本能不能开始测 | 13 项固定检查全绿，3 分钟内跑完，退出码 0 | 每批迭代**开场** |
| **回归** | 老功能有没有被改坏 | 全部已验收任务的验收清单均有对应用例且全绿；覆盖率不低于上次 | 每批迭代**收尾**、发版前 |

补充两层（对应 AI 自动化测试）：

| 层 | 内容 | 工具 |
| --- | --- | --- |
| 脚本功能测试 | 由 AI 编写的后端集成与单元用例 | pytest |
| UI 自动化 | 关键路径真实浏览器操作 + 组件级单测 | `@playwright/test`、Vitest |

## 4 工具与版本

| 用途 | 工具 | 锁定版本策略 |
| --- | --- | --- |
| 后端测试运行 | `pytest` + `pytest-django` | 写入 `backend/requirements-dev.txt`，与运行依赖分离 |
| 覆盖率 | `pytest-cov` | 同上 |
| 并发用例 | 标准库 `concurrent.futures` | 不额外引入依赖 |
| 前端单测 | `vitest` + `@vue/test-utils` + `happy-dom` | `package.json` devDependencies 锁定精确版本 |
| UI 回归 | `@playwright/test` | 用 `channel: "chrome"`，**不下载 chromium** |
| 冒烟脚本 | PowerShell 7（本机已有） | 零额外依赖 |

> 已安装的 Playwright **MCP** 是给 AI 操作浏览器用的交互通道，不是测试执行器，两者互不复用。

## 6 环境与配置要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 测试库权限 | `shop` 账号需 `CREATE`/`DROP`，或本地用 root 跑测试 | 当前本机用 root：`$env:DB_USER="root"; $env:DB_PASSWORD=...` |
| 建库加速 | `--reuse-db` + `--create-db`（结构变更时） | 现有 13 条用例整轮约 33–100 秒，主要耗在建 schema |
| 并发用例 | 单独标记 `@pytest.mark.concurrency`，默认不随快速回归跑 | 涉及 `transactional_db`，较慢 |
| 前端 E2E | `channel: "chrome"` + `fullyParallel: false` | 避免与新增 chromium 下载冲突 |
| 前端 E2E 依赖 | Vite dev server（5173）+ Django（8000）需先启动 | 由 `webServer` 配置托管，或由 `test-all.ps1` 预启动 |
| 数据隔离 | 每个用例自建用户，命名带随机后缀 | 禁止依赖 `seed_demo` 数据，避免相互污染 |

## 7 执行门禁与节奏

| 时机 | 命令 | 时长目标 | 失败处理 |
| --- | --- | --- | --- |
| 每批迭代**开场** | `powershell -File scripts/smoke.ps1` | ≤ 3 min | 停止开发，先修环境或回滚 |
| 每次提交前 | `pytest backend/tests/integration -q` | ≤ 2 min | 禁止提交 |
| 每批迭代**收尾** | `powershell -File scripts/test-all.ps1` | ≤ 8 min | 视为未交付，不得登记验收 |
| 发版前 | `test-all.ps1 -Full`（含 concurrency、E2E 全量、覆盖率） | ≤ 20 min | 阻断发版 |

门禁规则：

1. 冒烟失败 → 该批迭代不能开始，不允许「边修边开发」。
2. 集成失败 → 不允许提交；若确属他人遗留，须记录缺陷编号后单独提交修复。
3. 回归失败 → 任务状态只能登记「开发中」，不能登记「AI 已交付」。
4. 三层全绿是登记 `docs/acceptance/**` 中「自动测试和自检证据」字段的前提。

## 8 覆盖率与棘轮

架构要求：后端整体行覆盖 ≥ 80%，交易相关 Service 分支覆盖 ≥ 90%（I10-T01）。

分阶段策略：

| 阶段 | 目标 | 说明 |
| --- | --- | --- |
| B1 完成 | 跑出基线数字 | 当前预计 15–25%，仅地址模块 |
| I02 收尾 | ≥ 50% | 认证与地址全覆盖 |
| I03 收尾 | ≥ 65% | 商品与 CMS 覆盖 |
| I04 收尾 | ≥ 70% | 订单主流程覆盖 |
| I10 前 | ≥ 80%，交易分支 ≥ 90% | 达架构要求 |

**棘轮规则**：`docs/testing/覆盖率基线.md` 记录每批数字，新一批覆盖率低于基线即判定回归失败，除非在提交说明中写明理由并经人工确认。

## 11 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 测试库建库权限不足 | 测试无法启动 | 给 `shop` 补 `CREATE` 权限；或本地用 root 并通过环境变量注入 |
| schema 重建慢 | 单轮回归超过 2 分钟 | `--reuse-db`；`transactional_db` 仅用于并发用例 |
| `TestCase` 无法验证行锁 | 并发结论假通过 | 强制使用 `transactional_db`，并在用例中断言超时行为 |
| Playwright chromium 缺失 v1255 | E2E 起不来 | `channel: "chrome"` 复用系统 Chrome |
| E2E 依赖两个 dev server | 启动不稳定 | `webServer` 配置 + 健康检查等待；`test-all.ps1` 统一托管 |
| 三层全量拖慢迭代 | 每批超 30 分钟 | 冒烟优先；集成按迭代增量补；并发与 E2E 放发版前 |
| 覆盖率冲刺与功能开发冲突 | I10 无法达标 | 每批只要求「不降低」，冲刺集中放 I10-T01 |
| 用例与验收清单脱节 | 回归跑绿但仍不合格 | 用例 docstring 必须标注任务 ID；矩阵缺失即门禁失败 |

## 12 度量指标

| 指标 | 目标 | 采集方式 |
| --- | --- | --- |
| 冒烟通过率 | 100% | 冒烟 JSON |
| 集成用例数 | 每迭代净增 ≥ 5 | pytest 计数 |
| 回归逃逸缺陷 | 0（发版后发现的旧功能缺陷） | 缺陷登记 |
| 回归总时长 | ≤ 8 分钟（不含并发） | pytest `--durations` |
| 后端行覆盖率 | 逐批棘轮上升，I10 前 ≥ 80% | coverage.xml |
| E2E 稳定性 | 连续 10 次运行无 flaky | 重跑统计 |
